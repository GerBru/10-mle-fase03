Regressão de infraestrutura — corrigida

Docker/CD publicava imagem sem o modelo carregado

Ao mover models/preprocessor.joblib, best_baseline.joblib e model_config.json do git para o DVC (Atividade 5), um clone limpo — exatamente o que o runner do GitHub Actions vê — passou a receber uma pasta models/ vazia. O docker build continuava passando e o container subia normal, só que servindo model_loaded: false — uma falha silenciosa em produção.

Já existia antes, parcialmente: testamos o commit anterior a toda a Semana 1 e o mesmo sintoma já ocorria — mlp_model.pt nunca esteve no git (já era ignorado desde a Fase 1). O trabalho desta semana ampliou o problema de 1 para 3 arquivos ausentes, mas não o criou.

Correção aplicada: o Dockerfile agora falha o build se os três artefatos não estiverem no contexto, e o workflow de CD roda dvc pull antes de construir a imagem. Como o remote atual do DVC é uma pasta local (decisão da Semana 1), inacessível pelo runner, o CD passa a falhar alto — em vez de publicar uma imagem quebrada silenciosamente.

Pendência em aberto: o deploy automático via CD fica bloqueado até o remote do DVC migrar para algo acessível pela CI (ex.: S3). Decisão de infraestrutura para revisar na Semana 2 ou 3.
